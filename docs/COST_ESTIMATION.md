# 文件成本估算

## 畫面上的三個數字

- **已花費**：API 回報用量依每次請求的模型價格換算，跨暫停及歷史續翻累積；不是供應商帳單查詢。
- **剩餘預估**：未完成原文的各階段預估，加上近期完成段落的實測校正。已完成擷取、分析不再加入。
- **預計完成總額**：已花費 + 剩餘預估。規劃範圍不是統計信賴區間，也不是最高費用承諾。

最終帳單仍以供應商為準。缺少 usage 的失敗／中斷請求、價格異動、特殊長上下文級距、稅金等，都可能造成差異。

## 原文字數

Markdown 與 PDF 都使用同一個文字 token 估算器：CJK 字元約一個 token，其他文字每四個字元約一個 token。這不是供應商 tokenizer。

上傳 PDF 時先在瀏覽器讀取原生文字，不呼叫付費 API、不用壓縮檔案 bytes 或 PDF 圖像 token 代替原文字數。若有稀疏頁面（少於 20 個非空白字元），保守標示待擷取後估算。封面／空白頁也可能觸發此標示；有文字層的圖片內容仍可能無法預測。

PDF 擷取完成後，依真正送入翻譯的 Markdown 重算，並以相同 Markdown/token 分段器計算剩餘內容；原生 PDF 預估不再覆蓋已確認文字。

## 階段與提示詞

`cost-prompts.ts` 計算現行提示詞模板、JSON schema、術語表、角色及文件記憶的文字長度。`cost-forecast.ts` 分別估計擷取、分析、初稿、逐段校對、漏譯補修、風險句複審、章節校稿及重試。

- 風險句複審使用實際路由的 reviewer 模型價格，不套用初稿模型價格。
- 已確認全為原生文字的 PDF 不再預估 AI 擷取費用；OCR 改為逐頁處理，未知掃描來源仍標示待估算。分析在完成擷取後依實際全文取樣長度計算。
- 初稿／校對包含來源句子標記、譯文擴張、結構化輸出及推理餘量；前文原譯各 1,000 字另預留約 1,250 tokens。
- 初始模型假設可見輸出及標記約原文 token 的 1.6 倍；各階段另有固定輸出餘量。補修與風險句複審採預期比例，不假設每段一定觸發。
- 章節以最多六段為基礎估計；小說／法律採較高涵蓋率，其他文件採部分涵蓋率。實際自然章節邊界與風險決策可能不同。
- 重試餘量只加在初稿／校對／補修循環；不把一次性語意複審乘上重試次數。
- 預估不先假設快取命中。實測用量會反映快取與推理；推理已包含於計費輸出，不再重複加價。

上述倍率／機率都是初始規劃假設，不是實際 token 數、官方費率或模型品質保證；本次不更動模型、價格、翻譯品質或推理設定。

## 動態校正與續翻

只在整段翻譯與必要校稿成功提交後記錄樣本；不把串流中的段落視為完成。樣本保留原文 tokens、費用與設定指紋，不保存提示詞或文件內容。

至少三個相同模型／文件模式／章節校稿／重試／自訂指示設定的完成樣本才啟用校正。取最近最多 12 段，依總費用除以總原文 tokens 推估剩餘花費；實測權重從 25% 增至最多 80%，保留部分初始估算以涵蓋尚未發生的章節校稿。

目前段落已回報的費用會從該段預估扣除，但最多扣掉該段份額，不能抹掉其他未翻譯段落的費用。暫停／失敗後取消這項扣除，保留已花費並重新預估未完成段落。

樣本與階段／模型帳本隨歷史紀錄保存。舊紀錄有累積金額但沒有階段資料時顯示「舊紀錄／未分類」，不得用目前模型價格重算過去支出。完全沒有歷史 usage 的紀錄仍無法還原先前費用。

初始規劃範圍為剩餘估算的 60%–200% 加已花費；實測校正後為 75%–150% 加已花費。仍保留既有整份文件上限、逐次請求預留及輸出長度限制。

## 2026-09-04 中間結果與用量落盤

- requests store 保存精確請求雜湊與完整回應，模型／提示詞／schema／工作流程版本不同不共用結果。這是瀏覽器端的工作結果重用，不是供應商折扣快取。
- 正常完成回應的用量與結果先原子存入 IndexedDB，再做費用上限檢查及進入下階段。串流用量依增量即時保存；快取命中不再計費。
- 畫面規劃仍保守地估算未提交段落，尚未逐一扣除其中每個已快取階段；真正發出新請求前才做預算預留。
- 未收到最終用量的中斷請求保持待確認；顯示總額可能低於供應商帳單。沒有遠端冪等／帳單查詢，不能保證中途關閉後重試完全沒有重複計費。
- Web Locks 僅保護同一瀏覽器與網站來源的分頁；不同裝置不在鎖定範圍內。
